# 房间地图验收（2026-11-21）

## 正式部署

- 正式入口为 [匕首港](https://screenol.pages.dev/) 的房间「战斗」旁「地图」按钮。
- Pages 部署为 `aebf4e55`，Worker `dhol-realtime` 版本为 `0f1bf566-54e0-4dce-947b-ee603f92626f`。本次用 Wrangler 直接发布工作区构建。

## 交互与同步

正式站点用两个隔离的 Chromium 浏览器会话通过验收。验证了 40×40 地图和约 30×20 的初始视野、滚轮缩放、右键平移、Token 新增与删除、拖动时的本地预览、松手吸附、同格重叠、名称和名牌底色同步。画笔颜色和粗细同步，采样简化保留拐角。两人同时抬笔后两条线均保留，观察者可擦除发起者的整条笔迹。

## 恢复与兼容

- 浏览器模拟抬笔时断线，确认待保存笔迹关闭面板再打开后仍在，重连后按原请求 ID 重发。模拟服务端已提交、发起端漏收正式事件和回执，确认重连快照补齐状态。模拟服务端拒绝超出消息字节上限的笔迹，确认笔迹只在发起端标记失败且仍可擦除。
- workerd 中用真实 SQLite 验证重复请求返回原回执、重复删除不增加序号、已删除 Token 的迟到移动不使其复活、回执写入失败时事务回滚，以及旧版连接继续收到兼容快照。导出的地图完整恢复，缺少地图字段的旧备份恢复为空地图。
- 首版上限是单次地图消息 16 KiB、每条笔迹 512 点、每图 512 KiB 地图数据、128 个 Token 和 256 条笔迹。真实 SQLite 测试填至字节上限附近，验证继续添加会被拒绝，擦除后可再次添加。图片标识 `hero`、`beast`、`skull`、`marker` 随 Token 持久化。

## 延迟

使用独立 Stage 8 Worker 和 Pages，连接端在同一 Windows 环境。Cloudflare Trace 为 `NRT / JP`，按本轮确认使用当前东京出口。历史香港样本有独立的网络条件，基准保存在[阶段八验收](room-v2-validation.md#阶段八掷骰链路与架构独立性2026-10-10)。

浏览器以点击掷骰、松手或擦除点按为起点，通过 DOM 的正式记录或笔迹确认状态取终点。字节数为 UTF-8 JSON 大小。P50/P95 使用最近秩百分位数。并发阶段每轮由三名画图者各抬笔一次，同时由第四名成员掷骰；交错阶段在画图操作之间交替掷骰。

30 秒内无房间消息后，在 4 个独立浏览器房间测试首掷。点击至正式显示的 P50/P95 为发起端 208/341 ms、观察端 213/272 ms。另在 6 个独立合成房间测得从 WebSocket 发送到正式收帧的 P50/P95 为发起端 191/605 ms、观察端 190/191 ms。两组服务端排队均为 0/0 ms。70 秒试验超时，未获得可用的 P50/P95。

容量场景恢复了 75 条各 512 点的笔迹，地图数据 521,465 字节，约为上限的 99.5%。12 次重连均保留完整地图，快照共 522,004 字节。发出同步请求到收到快照的 P50/P95 为 514/5,916 ms，主动关闭 WebSocket 到客户端恢复就绪为 2,563/7,904 ms，后一项包含连接重试等待。

浏览器验收和测量可通过 Playwright CLI 运行。打开正式站点或 Stage 8 页面后，使用 `run-code --filename scripts/check-room-map-browser.js` 复查交互。测量时打开 Stage 8 页面并使用 URL 片段 `#warm`、`#capacity`、`#idle-30` 或 `#idle`，再运行 `run-code --filename scripts/measure-room-map-browser.js`。测量结果写入 `.wrangler`。
